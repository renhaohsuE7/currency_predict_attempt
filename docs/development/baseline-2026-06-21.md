## Phase 0 quick-fix(config-only,不改 runtime 行為)

收集階段原本 8 個檔案直接 `ModuleNotFoundError: No module named 'src'`,因為測試混用兩種 import 風格:

- `from currency_predictor...`(由已安裝套件解析,OK)
- `from src.currency_predictor...`(需要 repo root 在 `sys.path`,預設 pytest `prepend` import mode 不會放入)

修法:`pyproject.toml` 新增 `[tool.pytest.ini_options] pythonpath = ["."]`(並註冊 `slow` marker)。純設定,不動任何原始碼行為。修完 16 檔全部可收集。

## 28 個 pre-existing 失敗的分類(全部與重構前的舊架構漂移有關)

### A. API 漂移 — 測試指向已改名/已移除的方法或簽名(18)

| 測試 | 原因 |
|---|---|
| `test_config_manager::test_init_without_file` | 期望預設模型名 `'PatchTST'`,現碼回 `'patchtst_sklearn'` |
| `test_currency_predictor::test_setup_default_models` / `test_train_model` / `test_predict` / `test_evaluate_model` | `CurrencyPredictor` 已無 `setup_default_models`(facade 公開 API 已改) |
| `test_data_processor::test_create_lagged_features` | `create_lagged_features()` 不再接受 `target_column=` |
| `test_data_processor::test_scale_features` | `scale_features` 簽名改變(`X has 126 features, scaler expecting 168`) |
| `test_data_storage::test_save_and_load_processed_data` / `test_data_exists` / `test_delete_data` / `test_get_data_info` | 現 `DataStorage` 無 `save_processed_data` / `data_exists` / `delete_data`;`get_data_info` 簽名改變 |
| `test_data_storage::test_save_invalid_data` | `assert True is False`(舊預期) |
| `test_models_patchtst::test_init_default_params` / `test_get_model_info` / `test_model_reproducibility` | 模型 `name` 現為 `'PatchTST_Sklearn'`,測試期望 `'PatchTST'` |
| `test_prediction_pipeline::test_validate_config_valid` / `test_collect_data_stage` / `test_save_results` / `test_generate_report` | `PredictionPipeline` 私有方法改名(`_validate_config`/`_collect_data`/`_save_results`),`_generate_report` 多了 `timestamp` 參數 |

### B. 格式器 emoji vs ASCII(6)

`test_result_formatter::*` — 現碼輸出 `[OK]` / `[FAIL]`,測試期望 `✅` / `❌`。
(碼被改成 ASCII 應是為了避開 Windows cp950 編碼錯誤;測試未同步更新。)

### D. 與本次重構**相關**的紅(1,需注意)

- `test_training_issues::test_patchtst_fit_rejects_validation_split` — 期望 `fit()` 對 `validation_split` **raise TypeError**,現碼「DID NOT RAISE」。
  - **與 Task 5(統一 fit() 介面)直接相關**:統一後 `fit(self, X, y, validation_data=None, **kwargs)` 會吞掉/忽略未知 kwargs,與「reject」的舊預期相衝。此測試**現在就是紅**(不在綠集合),Task 5 後仍紅屬預期,非回歸。Task 5 完成時在評估/重構紀錄載明此抉擇。
